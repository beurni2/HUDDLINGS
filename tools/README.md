# Tools

Production tools that never ship in the app.

- `copylint/`: the copy lint (rule R7 and section 20). It fails the build on banned words, exclamation marks, the literal word Mochi outside feature names, unknown placeholders and printf specifiers, the words notifications may not use, names on the Lock Screen and placeholders in InfoPlist copy. Run `python3 tools/copylint/copylint.py`; its tests run with `python3 -m unittest discover -s tools/copylint`.
- `copy/catalogue.json` (at the repository root) is the single source of user-visible copy. The app's string catalogues, the notification templates in `server/` and the web page's copy are generated from it when each is built, never written inline; the lint also reads every `.xcstrings`, `.strings`, `.stringsdict` and `Info.plist` file and the Info.plist properties in `ios/project.yml`. `python3 tools/copylint/spec_catalogue.py --write` regenerates the catalogue from the spec.
- `precommit.sh`: what runs before every commit, on the staged files: the copy lint and its tests, the app code's strings, the QA tools' tests, the hook's own tests (`test_precommit.py`, which run it in a small repository of stand-ins), the reference prep's tests (and, when a commit touches it, a check that each species' `ref/` and `model.json` are what the prep writes), the sheet match's tests (run beside the rest, on their own copy of `characters/`, so neither that check nor the front's build changes what they read) and the placement guide's, the runtimes' typecheck and tests (the kit's and the dog's included), and a check that the shared test vectors are current. When a commit touches `characters/dog/src`, `characters/draw`, `characters/build`, `runtime-web/lab` or `characters/sheetmatch`, it can also build the dog from the committed source, with the repository's raster cache, and run the front's sheet match as CI does (`look.ts dog front`, about 5 s), failing the commit when the match fails and leaving the evidence in `build/qa/front/`. That step is off until the front passes its match: `HUDDLINGS_FRONT_MATCH=1 git commit …` runs it, and once the front passes it becomes the default by removing the variable's test in the hook. A fast Visual QA subset joins in phase 4. The SessionStart hook turns it on (`git config core.hooksPath .githooks`); outside Claude Code, run that command once.
- `guide/`: placement guides for drawing parts by hand (phase 3): `python3 tools/guide/grid.py dog front [--box x0 y0 x1 y1] [--still <dir>] [--trace]` writes `build/guides/dog/front.png`, the turnaround crop enlarged 6 to 8 times with a 5 pt grid in model space, the landmarks named, and optionally an onion skin of the current still and a potrace outline at 25%. It refuses to write under `characters/`, `build/characters/`, `ios/`, `web/` or `runtime-web/` (rule R8). Its tests run with `python3 -m unittest discover -s tools/guide`.
- `requirements.txt`: the Python tools of spec section 5b, pinned for Python 3.11 to 3.13.
